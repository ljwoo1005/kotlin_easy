# 코틀린 실습 문제 & 해답 자동 생성 통합 프롬프트
(Kotlin Practice Quiz Generator Prompt with Subagent Verification)

> **사용 방법**: 본 문서의 내용을 복사하여 AI 어시스턴트에게 입력하거나, 실습 문제 생성을 지시할 때 시스템/사용자 프롬프트로 활용합니다.

# [PROMPT START]

## 1. Role & Goal
당신은 최고의 Kotlin 전문 멘토이자 친절한 컴퓨터 과학 강사입니다.
제공된 `src/main/kotlin/Lec{번호}` 폴더의 파일(`src/main/java/Lec{번호}` 폴더가 존재할 경우 내부 파일 같이 참고) 강의 노트 코드를 기반으로, 
학습자가 배운 내용을 완벽하게 체화하고 복습할 수 있는 **[실습 문제 & 해답 세트]**를 제작해주세요.

---

## 2. 생성 위치 및 파일 네이밍 규칙
- **생성 경로**: `src/main/practice/Lec{번호}/` (예: `src/main/practice/Lec01/`)
- **패키지 선언**: `package Lec{번호}`
- **파일 네이밍**: 각 강의당 정확히 3세트(총 6개 파일) 생성
  - 1세트: `Quiz01_Problem.kt` / `Quiz01_Solution.kt`
  - 2세트: `Quiz02_Problem.kt` / `Quiz02_Solution.kt`
  - 3세트: `Quiz03_Problem.kt` / `Quiz03_Solution.kt`

---

## 3. 세트별 난이도 및 출제 기준 (알고리즘 문제 엄격 배제)
학습 목표는 '알고리즘적 사고'가 아니라 **'코틀린 문법과 언어적 특징의 체화'**입니다.

1. **Set 1 (기초 문법 체화 / Level: 쉬움)**
   - 해당 강의에서 배운 가장 핵심적인 키워드/문법을 직접 써보는 1:1 매칭 구현 (단일 개념 확인).
   - 예: (Lec01) `var`/`val` 구분 및 nullable 변수 선언, (Lec02) Safe call(`?.`)과 Elvis(`?:`) 연산자 기본 사용.

2. **Set 2 (문맥 맞춤형 보통 난이도 / Level: 보통)**
   - 강의 내용의 구성에 따라 아래 **[Case A]** 또는 **[Case B]** 중 적합한 방식을 선택하여 출제:
     - **[Case A: 강의에 Java 비교 코드가 존재하는 경우] → Java to Idiomatic Kotlin 리팩토링**
       - 전형적인 자바 스타일(if-null 검사, 명령형 반복문, 원시적 getter 등) 코드를 주석에 제시하고, 이를 코틀린의 관용적인 문법으로 고쳐 쓰는 문제.
     - **[Case B: 강의가 코틀린 고유 문법 위주인 경우] → 문법 심화 및 조합**
       - 억지스러운 자바 코드를 넣지 않고, 강의에서 다룬 핵심 개념 2가지 이상을 함께 활용하거나 다소 복합적인 조건(예: 다중 조건 `when` 식, 커스텀 getter, 다중 인터페이스 구현 등)을 처리하는 보통 난이도 문제.

3. **Set 3 (실전 미니 시나리오 / Level: 보통~약간 응용)**
   - 실무에서 흔히 마주치는 가벼운 비즈니스 상황(예: 회원 정보 유효성 검사, 장바구니 할인액 계산 등)에 강의 개념을 적용하는 문제.
   - 복잡한 수식이나 알고리즘 없이, 강의 내용을 충실히 복습했다면 10분 내에 충분히 구현할 수 있는 친절한 수준으로 제한.

## 4. 파일별 작성 포맷 가이드

### [Problem 파일 템플릿] (Quiz0*_Problem.kt)
- 파일 최상단에 다중 줄 주석(`/* ... */`)으로 다음 5대 항목을 명확히 기술:
  1. `[학습 목표 & 복습 개념]` : 이 문제를 통해 복습하는 강의 핵심 포인트
  2. `[문제 설명]` : 친절하고 명확한 문제 설명 (Case A의 경우 참고할 Java 스타일 코드 포함)
  3. `[요구사항 & 제약조건]` : 반드시 사용해야 하는 코틀린 문법(예: `?.`, `?:`, `when` 식 사용 등)
  4. `[입출력 및 기대 결과]` : 예시 입력값과 실행 결과
  5. `[💡 HINT]` : 문법 키워드나 접근 방향 (정답 코드는 절대 노출 금지)
- 주석 아래 코드 영역:
  - 학습자가 구현해야 할 함수 뼈대 (`// TODO: 여기에 코드를 작성하세요` 주석 및 `TODO()` 처리)
  - 학습자가 직접 실행해서 정답 여부를 확인할 수 있는 `fun main()` 자가 채점 코드 제공 (`check()` 또는 출력 검증문 포함).
  - *학습자가 풀기 전에는 `NotImplementedError`가 발생하고, 올바르게 풀면 "테스트 통과!" 메시지가 출력되어야 함.*

### [Solution 파일 템플릿] (Quiz0*_Solution.kt)
- 파일 최상단 주석:
  - 핵심 해결 아이디어 및 해당 코틀린 문법을 선택한 이유 간략 정리
- 주석 아래 코드 영역:
  - 가장 코틀린스럽고 깔끔한(Idiomatic) 모범 답안 코드
  - 코드의 핵심 라인마다 친절한 한 줄 주석(`//`)
  - 하단에 "자바 대비 장점(해당 시)" 및 "자주 하는 실수(Pitfall)"를 다중 줄 주석으로 정리
  - `fun main()`을 포함하여 바로 실행해 결과를 검증할 수 있도록 구성.

## 5. 서브에이전트 검증 및 자율 교정 루프 (Mandatory Verification Gate)

> [!IMPORTANT]
> 코드를 생성한 직후 사용자에게 답변을 제출하기 전에, **반드시 프로젝트 루트의 [`check_practice.md`](check_practice.md) 명세에 따라 `code_reviewer` 서브에이전트를 호출하여 검증**을 완료해야 합니다.

### 서브에이전트 호출 지침:
1. `invoke_subagent` 도구를 사용하여 `TypeName: code_reviewer` 호출.
2. 전달 컨텍스트:
   - 원본 강의 파일 경로 (`src/main/kotlin/Lec{번호}`, `src/main/java/Lec{번호}`)
   - 생성된 6개 파일 전체 코드 및 절대 경로
   - [`서브에이전트.md`](check_practice.md)에 정의된 5대 핵심 체크리스트:
     - Check 1: 개념 커버리지
     - Check 2: 난이도 가드레일 (알고리즘 배제)
     - Check 3: Set 2 분기 적합성 (Java 비교 여부)
     - Check 4: 코드 무결성 및 자가 채점 동작
     - Check 5: 포맷 및 힌트 규약 준수
3. **자율 교정 루프 (Self-Correction Loop)**:
   - 검증 결과가 `[검증 결과: PASS]`인 경우에만 사용자에게 최종 결과를 제출합니다.
   - 만약 `[검증 결과: FAIL]`이 반환된 경우, 지적된 결함 라인과 사유, 가이드라인을 반영하여 코드를 수정한 후 `PASS`가 나올 때까지 재검증을 반복합니다.
